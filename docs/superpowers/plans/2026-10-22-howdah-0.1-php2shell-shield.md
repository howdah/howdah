# Howdah 0.1 "PHP2Shell shield" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Howdah 0.1, a defensive PHP extension that blocks abusive `multipart/form-data` requests (the PHP2Shell / CVE-2026-109618 shape, CVE-2023-0662) before PHP allocates per-part memory, on PHP 5.4–8.5, delivered as a signed tarball plus build-from-source with a one-page site.

**Architecture:** A pure-Rust core (no PHP types) does all parsing, limit-checking, rule decisions and logging. A thin per-generation C-ABI glue layer (`cdylib`) registers Howdah as a PHP extension at module startup, chains PHP's existing `rfc1867` multipart callback, feeds streaming upload events to the core, and aborts the request the moment a limit trips. The core is unit-tested and fuzzed on the host; the glue is integration-tested against real PHP in Docker.

**Tech Stack:** Rust 1.99 (workspace: `howdah-core`, `howdah-sys`, `howdah-ext`), `bindgen` for per-version PHP headers, `cargo-fuzz`, Docker lab images per PHP minor, `manylinux2014` (glibc 2.17) for release builds, Astro for the site, GPG + SHA-256 for signing.

**Spec:** `docs/superpowers/specs/2026-10-22-howdah-design.md`

## Nature of this software (read first)

Howdah is a **defensive web application firewall**. Every component exists to *recognize and stop* abusive input before PHP is harmed. This plan produces no exploit, no RCE chain, and no attack tool.

**Test fixtures reproduce only the harmless structural shape of an abusive request** — e.g. "a multipart body with 20,000 empty parts" or "a part with 5,000 headers" — expressed as counts and sizes. They contain no shellcode, no payload, and nothing that achieves code execution. Their sole purpose is to assert that Howdah blocks the request. A fixture that would do damage if it reached an unprotected server must not be written; the shape is enough, because the shape is what the memory-exhaustion defense keys on.

## Global Constraints

Every task's requirements implicitly include these (exact values from the spec):

- **PHP versions:** 5.4, 5.5, 5.6, 7.0, 7.1, 7.2, 7.3, 7.4, 8.0, 8.1, 8.2, 8.3, 8.4, 8.5. NTS, non-debug. (PHP 5.4 has no official Docker image; its lab image builds PHP from source.)
- **Platform:** Linux x86_64 only in 0.1. aarch64 is 1.0.
- **SAPIs:** PHP-FPM, Apache `mod_php` (prefork), php-cgi/FastCGI.
- **glibc baseline:** release `.so` built against glibc ≤ 2.17 (CentOS 7) so one binary per PHP minor runs on CentOS 7, Ubuntu 14.04+, Debian 8+ and newer.
- **Config namespace:** all ini directives are `howdah.*`; the config/rules file is TOML.
- **Name in all artifacts:** extension, crate, `.so`, log dir `/var/log/howdah`, tool `howdah-check`. The name must not contain "PHP" (PHP License).
- **Modes:** `off` / `detect` / `block`. Critical limits block even when `howdah.mode=detect`; a critical rule only drops to detect if named explicitly.
- **Never crash the host:** invalid config → log a loud error, fall back to built-in safe defaults, let PHP continue. A panic in the core must never unwind into PHP; the FFI boundary catches it.
- **Privacy:** logs never record bodies, cookies, or auth headers by default.
- **License:** dual MIT / Apache-2.0. **Honesty:** no claim ships without a test that proves it.

## Review Focus

Input classes/failure modes the spec implies that no single task's happy-path tests fully exercise — each gets a test in the owning task:

1. **A legitimate large upload with many small fields** (e.g. a CSV import form, 500 fields) must pass untouched — false positives are the top anti-goal. → false-positive corpus, Task 12.
2. **A multipart body that streams in slowly / in many small network chunks** must be counted correctly across chunk boundaries — the analyzer is fed partial buffers, not whole bodies. → Task 3.
3. **`session.upload_progress.enabled` both on and off** — the defense must hold regardless, and must not break when another extension (session) owns the same callback. → Task 9 + Task 12.
4. **A malformed/truncated multipart body** (bad boundary, missing final delimiter, conflicting `Content-Disposition`) must be rejected or safely ignored, never crash the parser. → Task 3.
5. **The core panicking mid-request** must be contained at the FFI boundary and fail safe (PHP continues, event logged), never unwind into PHP. → Task 7.

### Task 1: Lab harness + hook-point spike (Milestone 0 — GATE)

- [ ] **Step 2: Run, verify fail.**
