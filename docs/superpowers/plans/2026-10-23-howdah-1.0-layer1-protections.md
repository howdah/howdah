# Howdah 1.0 — Complete Layer-1 Protections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend Howdah from the 0.1 critical-multipart subset to the *complete* Layer-1 protection set from design §5.3 — input-shape limits (variable count, array nesting depth, key length), request-header limits, and the known-CVE virtual patch for php-cgi argument injection (CVE-2012-1823) — with honest per-version coverage.

**Architecture:** All detection logic stays in the pure-Rust `howdah-core` crate (new `input.rs` module + extensions to `limits.rs`), exercised by host-only unit tests. A new per-generation glue hook family in `howdah-ext` feeds the core: the `sapi_module.input_filter` chain reports each registered request variable, and a request-start check reports the CGI query string and request headers. New rules flow through the existing `decide()` engine and the existing stashed-log / sticky-worst-action flow, so block/detect/off and per-rule overrides behave exactly as in 0.1.

**Tech Stack:** Rust (workspace crates `howdah-core` pure-Rust, `howdah-sys` bindgen bindings, `howdah-ext` cdylib), TOML config (serde), bindgen against php5/php7/php8 headers, the existing container lab matrix (php-fpm / Apache / cli-server) and false-positive corpus.

**Spec:** `docs/superpowers/specs/2026-10-22-howdah-design.md` (design §5.3 "Layer 1 protections", §5.4 honest coverage, §8 install/verify, §9 build/testing). This plan implements only the **complete-Layer-1** subsystem of 1.0; aarch64, apt/yum repos, the install picker, the Wasm demo, and the full site are separate 1.0 sub-plans.

## Global Constraints

- **Target PHP versions:** 5.4, 5.5, 5.6, 7.0–7.4, 8.0–8.5, Linux x86_64, NTS, non-debug. (aarch64 is a separate sub-plan.)
- **SAPIs:** PHP-FPM, Apache `mod_php` (prefork), php-cgi/FastCGI.
- **Never take PHP down (anti-goal #1):** invalid/unreadable config → `Config::safe_defaults()` (Block); every FFI entrypoint runs inside `catch_unwind` and fails **open** (returns Allow / 0) on panic; a glue bug must never unwind into PHP.
- **Mode semantics (unchanged from 0.1):** Critical rules block even when global mode is `detect`; global `off` disables everything; Standard rules follow the global mode (which ships at `detect`); an explicit per-rule override wins over both. Enforced solely by `rules::decide`.
- **Action codes pinned:** Allow=0, Log=1, Block=2 (`howdah-core/src/ffi.rs`).
- **No overclaiming (anti-goal #2):** every rule has a core test proving it fires AND a false-positive test proving it does not fire on legitimate traffic; the coverage table states exactly what each new rule does and does not cover, per PHP version/SAPI. Where a check cannot run on some SAPI/version, the coverage table says so rather than implying protection.
- **Reproducer disclosure (design §9):** tests recreate only the harmless request *shape* (counts, depths, lengths), never an exploit payload or RCE chain; any runnable attack-shape generator stays out of the public repo (the existing `/lab/spike/*` + `/private/` gitignore rules).
- **Privacy (design §5.7):** never log request bodies, cookie values, auth header values, or query-string values. Request variables and headers are reported to the core as **lengths and structure only** (names may be inspected transiently in glue for the self-test/CGI shape but are never logged).
- **Build requirement:** `panic = "unwind"` (workspace profiles); the runtime guard `panic_unwinds()` and its CI assertion stay green.
- **License:** dual MIT OR Apache-2.0 headers/semantics as in existing files.

## Review Focus

- **Legitimate large/structured form near the limits:** a real form with ~1500 fields or a legitimately nested survey (`answers[section][question][choice]`) must produce **zero blocks** at the shipped defaults. → Task 9 false-positive corpus; defaults set in Task 9.
- **urlencoded (non-multipart) attack path:** the variable-count / nesting / key-length checks must fire for `application/x-www-form-urlencoded` and query-string input, not only multipart — otherwise the flood just switches content type. → Task 1 spike proves the `input_filter` path covers both; Task 7 lab test sends a urlencoded flood.
- **CGI virtual patch false positive:** a normal query string containing `-` mid-value (`?q=a-b-c`, `?sort=-price`) must **not** fire; only the CVE-2012-1823 shape (no `=` present, leading `-`/`+` option) fires, and only under the CGI/FastCGI SAPI. → Task 3 (shape) + Task 8 (SAPI scoping).
- **Nesting-depth off-by-one:** depth counted from bracket structure must match PHP's own counting (`a`=0, `a[b]`=1, `a[b][c]`=2) so the limit lines up with `max_input_nesting_level`. → Task 2.
- **Fail-open on every new entrypoint:** NULL ctx and an injected panic in `howdah_input_var` / `howdah_query_string` / `howdah_request_header` must return Allow (0) and never unwind. → Task 5.

## Task 3: Core — CGI argument-injection virtual patch (CVE-2012-1823)

**Files:**
- Modify: `crates/howdah-core/src/input.rs` (the predicate)

**Interfaces:**
- Produces:
  - `pub fn cgi_arg_injection(query_string: &[u8]) -> bool` — true only for the CVE-2012-1823 shape: the query string contains no unencoded `=`, and its first non-whitespace byte (after optional leading `+`/`%20` run) is `-`.   - `pub fn check_query_string(&self, qs: &[u8], is_cgi: bool) -> Option<LimitHit>` on `Limits` — returns a `CgiArgInjection` Critical hit when `is_cgi && cgi_arg_injection(qs)`, else `None`. (The limit struct carries no tunable here; the rule is a fixed shape.)

    assert!(!cgi_arg_injection(b"a=1&b=2"));
    assert!(!cgi_arg_injection(b"sort=-price"));
    assert!(!cgi_arg_injection(b"q=a-b-c"));

## Task 5: FFI — panic-safe entrypoints for the new checks

**Files:**
- Modify: `crates/howdah-core/src/ffi.rs`

**Interfaces:**
- Consumes: `howdah_ctx`, its private `apply(Option<&LimitHit>)`, `InputState`, `Limits::check_input` / `check_query_string`.
- Produces three `#[no_mangle] pub unsafe extern "C"` entrypoints, each guarded by `catch_unwind` and returning an action code (0/1/2), fail-open on NULL/panic, folding into the same sticky `worst` + stashed-log flow as `feed`:
  - `howdah_input_var(ctx: *mut howdah_ctx, name: *const c_char, name_len: usize) -> i32` — the ctx holds an `InputState` (added as a field, reset in `request_begin`); records the var, runs `check_input`, applies the hit, returns `code(worst)`.
  - `howdah_query_string(ctx: *mut howdah_ctx, qs: *const c_char, qs_len: usize, is_cgi: i32) -> i32` — runs `check_query_string(qs, is_cgi != 0)`, applies, returns `code(worst)`.
  - `howdah_request_header(ctx: *mut howdah_ctx, name_len: usize, value_len: usize) -> i32` — records a header into `InputState`, runs `check_input`, applies, returns `code(worst)`. (Takes lengths only — names/values are never passed, per the privacy constraint.)
- Extend `describe()` with the six new `RuleId` arms.
- `request_begin` resets the new `InputState` field alongside the existing per-request reset.
