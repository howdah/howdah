# Howdah 1.0 — apt/yum package repositories (pkg.howdah.org / R2) Implementation Plan

> The highest-consequence 1.0 sub-plan: it produces signed apt + yum repositories whose URLs get written **permanently** into users' `sources.list` / `.repo` files (design §10). Build + validate + **stage**; the production go-live is owner-gated (see the Go-Live Ruling).

**Goal:** a reproducible pipeline that turns Howdah's per-version/per-arch release binaries into installable **Debian (.deb)** and **RPM (.rpm)** packages, assembles a **signed apt repo** (`dists/` + `pool/`) and a **signed yum repo** (`repodata/` + packages), and publishes them to the R2-backed `pkg.howdah.org` — so a sysadmin can `apt-get install php7.3-howdah` / `yum install php74-howdah` instead of unpacking a tarball.

**Architecture:** package building + repo assembly run in containers (the tools — `reprepro`/`aptly`, `createrepo_c`, `rpmbuild`, `rclone` — are not on the host; glibc-2.17 `.so`s come from the existing release pipeline / tarballs). Signing of repo metadata uses the CI signing subkey **in CI only** (the key is not local). The pure-Rust/glue code is unchanged. Publishing to R2 is an `rclone sync` in dependency order (design §10 builder notes).

**Spec:** design §10 (pkg.howdah.org on Cloudflare R2; repo layout rules: not tied to a distro codename; depend on the PHP API virtual package e.g. `phpapi-20180731`; RSA signing old apt/rpm can verify; HTTPS-only; upload order packages→indexes→`InRelease`/`repomd.xml` last; don't delete superseded; cache rules; `reprepro`/`aptly` + `createrepo_c`) and §8 (the apt/yum worked examples).

## Global Constraints
- **URLs are permanent** (design §10): the repo base URL `https://pkg.howdah.org/{apt,yum}`, the signing-key URL (`https://howdah.org/key.asc` / shipped `packaging/howdah-release-signing.asc`), and the layout must be FINAL before the first production publish. Decide them once here, matching §8's worked examples, and do not change them after go-live.
- **Signing happens in CI only** with `HOWDAH_GPG_SIGNING_KEY` (the existing release subkey secret); the public key users trust is `packaging/howdah-release-signing.asc`. Old `apt` (xenial) and `rpm` (CentOS 7) must be able to verify it. Local validation uses a THROWAWAY key, never the real one.
- **HTTPS-only** (owner decision): repo is static files on `pkg.howdah.org` (R2 custom domain, already live). Pre-2018 apt needs `apt-transport-https` + `ca-certificates` first — a documented one-line prerequisite.
- **No distro-codename coupling** — one binary per PHP API across distros; packages depend on the `phpapi-<N>` virtual package (apt) / the right PHP (yum), not on a codename.
- **No overclaiming** — install docs describe only what the repo actually serves; anything not yet published is marked as such.

## GO-LIVE RULING (binding)
The production publish of the real signed repo to `pkg.howdah.org`, and storing the R2 API token as a GitHub Actions secret, are **owner-gated**: this sub-plan builds, container-validates (throwaway key), proves the R2 upload path against a **throwaway `/_selftest/` prefix** with the provided creds (upload → fetch via `https://pkg.howdah.org/_selftest/...` → delete), and wires the CI publish workflow — but does NOT publish the real repo or set the CI secret. Go-live is one documented owner step. Rationale: permanent user-config URLs + credential handling + a signed public publish are irreversible, security-sensitive, outward-facing actions beyond what unattended execution should fire.

## Tasks

### Task 1: Debian (.deb) packaging
**Files:** `packaging/deb/` (build script + control/templates), reusing the release `.so`s.
- Build one `.deb` per PHP minor per arch: payload = `howdah.so` into that API's `extension_dir` under the Surý/Debian layout (`/usr/lib/php/<api>/`), `howdah.ini` into `mods-available/` with a `phpenmod`-compatible priority, and `maintainer scripts` that enable the module (postinst `phpenmod`, prerm `phpdismod`) without taking PHP down. Depend on the `phpapi-<N>` virtual package so the package installs only against a matching PHP. Package name scheme matching §8: `phpX.Y-howdah` (and/or an API-based name) — pick and document the final name.
- Build in a container with `dpkg-deb`/`debhelper`. **Validate:** in a Debian/Ubuntu container, `dpkg -i` (or a local-repo `apt-get install`) the package against a matching PHP, then `php -m | grep howdah` shows it loaded, and `phpdismod`/purge cleanly removes it. Arch (`amd64`/`arm64`) correct.
- Commit scripts (not built artifacts).

### Task 2: RPM (.rpm) packaging
**Files:** `packaging/rpm/` (spec + build script).
- Build one `.rpm` per PHP minor per arch: payload into the Remi layout (`/opt/remi/phpXY/...` + `/etc/opt/remi/phpXY/php.d/` for the `.ini`), named e.g. `phpXY-howdah`, requiring the matching Remi PHP. Also note the stock-distro path variant where it differs.
- Build with `rpmbuild` in a CentOS 7 / EL container. **Validate:** in a CentOS 7 (and an Alma/Rocky) container with a matching PHP, install the `.rpm`, confirm `php -m | grep howdah`, and clean removal. Arch (`x86_64`/`aarch64`) correct.
- Commit scripts (not built artifacts).

### Task 3: Repo assembly + signing (throwaway-key validation) + install-from-repo test
**Files:** `packaging/repo/` (apt + yum assembly scripts).
- **apt:** assemble `dists/stable/main/binary-{amd64,arm64}/` + `pool/` with `reprepro` (or `aptly`); generate `Packages`/`Packages.gz`, `Release`, and a GPG-signed `InRelease` + `Release.gpg`. Not tied to a codename (use `stable`).
- **yum:** assemble a flat repo with `createrepo_c` (`repodata/`), GPG-sign `repomd.xml`; provide a `howdah.repo` `.repo` file template pointing at `https://pkg.howdah.org/yum` with `gpgcheck=1` and the key URL.
- **Validate end-to-end with a THROWAWAY GPG key** (generate in-container; never the real key): serve the built repo over a local static HTTP server and, in target-distro containers, add the repo + import the throwaway public key and run the real client install: `apt-get update && apt-get install <pkg>` on Debian/Ubuntu; `yum install <pkg>` on CentOS 7 — each must install, verify the signature, and load Howdah. This proves the signed-repo path works; CI swaps in the real key.
- Produce the final `sources.list`/`.repo` snippets + the key-import step, matching §8's worked examples. Commit.

### Task 4: CI publish workflow + R2 path proof + docs (go-live staged)
**Files:** `.github/workflows/publish-repos.yml` (new), `docs/` install docs, `packaging/repo/README`.
- **Workflow** (tag-triggered or `workflow_dispatch`): build the packages + assemble both repos (Tasks 1–3's scripts), **sign with `HOWDAH_GPG_SIGNING_KEY`** (import like `release.yml` does), then `rclone sync` to R2 in dependency order — packages/`pool/` first, then `Packages*`/`repodata/`, then `InRelease`/`Release.gpg`/`repomd.xml` LAST; never delete superseded packages in the same publish. Set Cloudflare cache rules per §10 (long for `pool/`+packages, short/bypass for `dists/`+`repodata/`). The workflow reads the R2 token from a secret (e.g. `HOWDAH_R2_TOKEN` / the `RCLONE_CONFIG_R2_*` set) — documented as an owner-set secret, NOT set here.
- **R2 path proof (using the provided local creds, safe):** install `rclone`, and with the env from `~/.config/howdah-r2.env` do a throwaway round-trip — `rclone copy` a tiny file to `R2:<bucket>/_selftest/<rand>`, fetch it via `https://pkg.howdah.org/_selftest/<rand>` (proves bucket+domain+creds+HTTPS all work), then `rclone delete` it. Record the result. Do NOT upload any repo content.
- **Docs:** `docs/install-apt.md` / `docs/install-yum.md` (or a section) with the FINAL, copy-pasteable add-repo + install + verify + rollback commands for the platforms in §8 (xenial/bullseye/jammy/noble + CentOS 7/Alma), honest about the prerequisite and that go-live is pending.
- **Go-live doc:** `packaging/repo/GO-LIVE.md` — the exact owner steps to publish for real: (1) set the R2 token as the CI secret, (2) run the `publish-repos` workflow, (3) verify `apt-get install`/`yum install` against the live URL. Commit.

## Review Focus
- **Signature chain old clients accept:** the repo metadata signature must verify under CentOS 7 `rpm`/`yum` and xenial `apt` (RSA, not an only-new-GnuPG construct). → Task 3 container install-test.
- **phpapi/PHP dependency correctness:** a package must install ONLY against its matching PHP API (wrong-API install must be refused), so users can't load an ABI-mismatched `.so`. → Tasks 1–2.
- **No real key / no real publish leaks:** validation uses a throwaway key; nothing publishes repo content to the real `pkg.howdah.org`; the R2 proof touches only `/_selftest/` and cleans up. → Tasks 3–4 + Go-Live Ruling.
- **Upload order / atomicity:** indexes/`InRelease`/`repomd.xml` uploaded AFTER packages; superseded packages not deleted — so a client mid-update never 404s or hits a hash-sum mismatch. → Task 4.
- **maintainer scripts never break PHP:** postinst/prerm enable/disable the module idempotently and never fail the package transaction in a way that wedges PHP. → Task 1.
