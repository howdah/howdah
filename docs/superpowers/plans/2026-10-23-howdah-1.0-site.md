# Howdah 1.0 — full marketing website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow the existing single-page Astro site at `site/` into the full multi-page howdah.org described in design §10 — home, install picker, coverage, docs, live demo, blog, community — on the identity and component system already in `site/src/styles/global.css`, deployed by the existing `pages.yml` on push to `main`.

**Architecture:** Static Astro 5 site, `output: 'static'`. A shared `Layout.astro` owns `<head>`, skip-link, status banner, header/nav, and footer; every page renders inside it. Astro i18n is configured with `en` as the sole, non-prefixed default locale and the layout threads `lang`/`dir` so translations drop in later without moving files (design §10 "i18n routing … RTL-ready"). All logic-bearing claims link to the test or doc that proves them (anti-goal: overclaiming). No JS except the install picker and the WASM demo; both progressively enhance.

**Tech Stack:** Astro 5, vanilla JS (picker + demo), self-hosted fonts, inline SVG. No new runtime dependencies. No third-party requests (enforced by `pages.yml`).

**Spec:** `docs/superpowers/specs/2026-10-22-howdah-design.md` (§10 site, §8 install/verify, §5 coverage, §3 the four layers). The live 0.1 home page `site/src/pages/index.astro` is the pattern for voice, honesty and markup.

## Global Constraints

- **Defensive framing only; never overclaim.** Every protection claim links to the test/measurement that backs it. No "unhackable", no fear-mongering. Reuse the exact honest hedges already on the home page (what was and wasn't verified; detect-before-block; "not a replacement for patching").
- **No third-party requests, no trackers, no cookies.** Fonts self-hosted. The `pages.yml` build step greps `site/dist` and fails on any external URL except `https://howdah.org`, `https://github.com/howdah/howdah`, `http://www.w3.org/2000/svg`, `https://your.site/`. **The package repo lives at `https://pkg.howdah.org` — this host MUST be added to that allowlist** or the build fails.
- **WCAG 2.2 AA.** Semantic landmarks, one `h1` per page, logical heading order, visible focus (already themed), 44px touch targets, labelled controls, `prefers-reduced-motion` honored, light + dark themes, tables with scope/caption, contrast AA. Works at phone width with a 16px gutter and no horizontal page scroll.
- **Works without JavaScript except the demo and the picker.** Both degrade gracefully (the picker shows a usable default + a link; the demo shows an explanatory fallback).
- **Reuse the design system.** Use the tokens, `.wrap`, `.btn`, `.note`, `.card`, `.facts`, `.tablewrap`, `.steps`, `.tag`, section rhythm from `global.css`. Page-specific CSS goes in that page's scoped `<style>` block, never duplicated into `global.css` by parallel tasks.
- **Released-1.0 voice.** The site now describes 1.0: apt/yum repos exist, the picker is the primary install path, manual tarballs remain the fallback. The 0.1 "early 0.x / scope narrow" banner copy is replaced by released-1.0 copy that still points first-timers at detect mode and the coverage table.
- **Copy is British-neutral plain English, present-tense, concrete.** Numbers come from `site/src/data/coverage.json` and `docs/`, never invented.
- Signing key primary fingerprint `11521035C600F63831F825512087B8720997807B`; repo base `https://pkg.howdah.org`; release base `https://github.com/howdah/howdah/releases`.

## Review Focus

- **External URL leak →** any page emitting a URL outside the allowlist fails `pages.yml`; the pkg host must be allowlisted and no stray CDN/analytics URL may appear. (Owned by Task 1; every task's build run re-checks.)
- **Overclaiming in the comparison table →** competitor rows must be factual, dated, and sourced to each project's own docs; no invented capabilities or benchmarks. A reasonable reader must not come away thinking Howdah does more than the tested, narrow thing. (Task 2.)
- **Picker emits a wrong/mismatched command →** e.g. a Surý `phpenmod` path on a Remi/RPM target, or an API number that doesn't match the chosen PHP minor; every generated command set must be internally consistent and match §8. (Task 3.)
- **No-JS breakage →** picker and demo pages must render meaningful content and not a blank/broken control with JS disabled. (Tasks 3, 5.)
- **Coverage drift →** the coverage page must render only from `coverage.json` (generated from the matrix), never hand-typed cells, so it can't claim an untested block. (Task 4.)
